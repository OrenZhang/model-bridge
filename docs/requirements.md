# 需求范围

## 产品目标

本机统一模型工具。用户把账号和模型接入一次，在 Codex 桌面端、Codex CLI、Claude Code 或其他 Agent 中选择使用。统一网关是默认且唯一的服务方式，不让用户额外开启聚合模式或路由模式。

## 已确定

1. 仓库为公开的 `OrenZhang/model-bridge`。
2. Windows、macOS；默认服务本机，可选择 `0.0.0.0` 监听以供同一局域网的其他设备使用。
3. ChatGPT 必须提供设备码登录；API Key 是独立接入方式。
4. Kimi、MiniMax、自定义兼容服务；后续按各厂商实际授权能力扩展。
5. 对外支持 Responses、Messages、Chat Completions；同时处理流式、工具调用、取消和用量。
6. Codex 内可见多个服务商的模型，避免每切一次模型就重写服务商配置。
7. “对外服务”提供本机网关接入与恢复原始认证。统一模式接入所有服务商的模型，无需客户端另行登录 OpenAI；原始模式恢复接入前的连接与认证，保留登录文件和不相关配置。账号、服务商与模型在各自入口管理。
8. 用量按客户端、账号、服务商、模型记录；未知、实测、估算、套餐额度必须区分。
9. 独立实现。参考同舟交互和设计，不抽取其源码。
10. 自动检测现有 Codex 登录，支持复用账号、选择默认账号/模型和恢复原客户端配置。
11. 配置或登录成功后自动获取模型；显式提供失败状态与手工补充方式。
12. 三种接口分别展示可复制的 Base URL 和完整请求地址，Messages 的客户端基础地址不重复拼接 `/v1`。

## 网络设置的最新约定

网络代理是可选连接能力，不是统一接口的前置条件。对照同舟的账号网络边界：哪个连接需要，哪个连接设置；其授权轮询、模型发现和推理请求使用一致网络策略。保留默认网络、直连、显式代理；不修改系统代理，不因代理失败自动直连。

独立“网络代理”导航已移除，入口收进连接设置。用户进一步确认需要导入自己的代理订阅，已加入独立实现的 mihomo 内核管理、订阅/本地 YAML 导入、节点选择与更新；使用时自动启动，不增加主流程开关。内核只绑定本机回环端口，不修改操作系统网络。

## 最终验收标准

- 安装后添加 ChatGPT 设备授权账号、Kimi 与 MiniMax 账号，在同一 Codex 模型目录看见可用模型。
- 每种服务完成真实的“读文件 → 修改文件 → 调用测试工具 → 继续对话”闭环，尤其检查工具 ID、思考历史和上下文保留。
- Claude Code 能完成同样任务，配置可恢复；其他 Agent 能按其协议使用。
- 不需要人工切换网关模式；服务间切换不污染其他账号的代理或正在执行的请求。
- 断网、代理失效、令牌过期、限流、客户端取消时返回明确结果，统计不把失败伪装成成功。
- Windows 与 macOS 都完成安装、登录、重启恢复、托盘退出和卸载验收。

当前实现与这些最终标准的差距见 [路线图](roadmap.md)。
