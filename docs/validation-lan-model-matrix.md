### 高速 Kimi 的工具选择限制

最初的强制选择探测中，`kimi-for-coding-highspeed` 对 `tool_choice=required` 返回 HTTP 400。拆分探测确认：去掉输出上限仍会失败；`auto` 搭配原有 3000 token 上限能成功调用工具。没有改写网关或伪装成强制选择成功。

该模型随后按 Agent 的常规 `auto` 工具选择方式重新完成六组测试，仍要求模型实际调用工具、参数匹配、回执有效及完整多轮通过。其他九个模型首轮使用 required，均通过；后续轮使用 none。报告保留原始六次负向探测和各组实际使用的工具选择方式。复现脚本默认 auto，模型不执行工具同样判失败。

[Kimi 官方工具选择说明](https://platform.kimi.com/docs/guide/use-tool-choice) 区分 auto、none、required，并说明工具选择为请求级参数；高速订阅模型的上述限制由本次真实调用确认，不由开放平台的统一文档推定。

## 同名模型合并与分发

原始模型 ID 完全一致的通道跨服务商、地址、API Key 和订阅合并，对外只显示一个名称。当前真实目录从 109 项合并成 106 个不同名称，没有生成的前缀或后缀。内部保留账号身份、各通道协议和凭据，不合并 token。

- 新对话按可用且具备请求能力的通道轮询，工具、图片或 thinking 等级不支持的通道不会收到该新请求。
- 多轮、工具结果、签名和 reasoning 固定原通道；原通道失效、被停用或不支持后续新增能力时返回明确错误，不把已有状态转给另一个账号。
- 认证失败或限流的通道暂时冷却，新对话避让；已发出的生成请求不自动重放。
- 模型开关同步控制同名通道，隐藏后不再进入公开目录，单独停用某个连接仍可保留其他同名通道。
- 不同的模型 ID 不按相似名称猜测合并；有单独版本或高速 ID 的模型仍各保留一项。

### 真实双通道验证

现有 `gpt-5.6-sol` 同时具有 ChatGPT 官方登录和 API Key 通道。通过同一个无前缀名称新建 4 个不同 session 的对话，每个对话再发送一条历史续接消息；对照真实用量记录：

| 通道 | 新对话 | 历史续接 | 结果 |
| --- | ---: | ---: | --- |
| channel-1 | 2 | 2 | 全部 HTTP 200，续接固定原通道 |
| channel-2 | 2 | 2 | 全部 HTTP 200，续接固定原通道 |

实际是按新对话均衡，并非在同一对话的每条消息之间轮换。准确区分不同会话可发送 `X-Model-Bridge-Session` 或 Codex 的 `session_id`；没有会话标识时，使用第一条用户消息识别会话，相同首条消息会被视为同一会话。

自动测试另外覆盖不同服务商/地址合并、API Key/订阅合并、并发轮询、原生 thinking 与工具回放、账号冷却、能力选择、已停用通道、持久化与旧会话归属迁移。

## 复现

先配置测试环境的网关地址与本地访问密钥，MODEL_BRIDGE_VALIDATION_MODELS 可填逗号分隔的原始模型 ID；未指定时测试目录内 Kimi/MiniMax 的全部模型。不要把密钥提交到仓库。

```sh
npm run build
node scripts/validate-lan-models.mjs
```

所需环境变量为 `MODEL_BRIDGE_TEST_GATEWAY_URL`、`MODEL_BRIDGE_TEST_GATEWAY_KEY`；可选 `MODEL_BRIDGE_TEST_CONCURRENCY`（默认 3）、`MODEL_BRIDGE_TEST_TOOL_CHOICE`（默认 auto）、`MODEL_BRIDGE_VALIDATION_REPORT`。真实调用消耗对应已授权通道的额度；模拟服务的测试不能替代这里的真实结果。
